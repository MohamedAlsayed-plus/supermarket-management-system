# نظام إدارة السوبر ماركت (الإصدار 2)

واجهة سطح مكتب **عربية بالكامل** مبنية بـ PySide6، تتصل مباشرةً بقاعدة بيانات **Microsoft SQL Server** (SupermarketDB). تضم لوحة تحكم، تنقلًا جانبيًا بأيقونات، إدارة المنتجات والموردين والمستخدمين، فواتير مبيعات وشراء ومرتجعات، سجل حركات المخزون، وتقارير ورسومًا بيانية، مع مظهر فاتح/داكن.

## المتطلبات

- Windows مع Python 3.11 أو أحدث.
- SQL Server (Express أو أي إصدار) متاح من الجهاز، مع صلاحية القراءة/الكتابة على `SupermarketDB`.
- برنامج **ODBC Driver 17 أو 18 for SQL Server** مثبّت (ضروري).
- SSMS اختياري لتنفيذ سيناريو SQL يدويًا.

## التثبيت

من مجلد المشروع:

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## إعداد قاعدة البيانات

لديك طريقتان:

1. افتح `sql/SupermarketDB.sql` في SSMS ونفّذه (ينشئ قاعدة البيانات والجداول والبيانات التجريبية).
2. من التطبيق: في نافذة الاتصال اضغط **«تهيئة قاعدة البيانات»**.

> ⚠️ التهيئة **تحذف كل الجداول** وتعيد إنشائها بالبيانات التجريبية؛ أي بيانات موجودة ستُحذف. اختر هذا الخيار فقط عند الرغبة في إعادة ضبط قاعدة البيانات بالكامل (وهو ما طلبته لهذا الإصدار).

## التشغيل

```powershell
python -m app.main
```

يعمل أيضًا: `python app/main.py`.

## الاتصال وتسجيل الدخول

عند بدء التطبيق تظهر نافذتان متتاليتان:

1. **الاتصال بقاعدة البيانات**: اسم السيرفر (مثل `localhost\SQLEXPRESS`)، اسم قاعدة البيانات، ونوع المصادقة (Windows أو SQL Server)، مع أزرار «اختبار الاتصال» و«تهيئة قاعدة البيانات» و«اتصال».
2. **تسجيل دخول المستخدم**: اختر المستخدم واكتب كلمة المرور. كلمات المرور مخزّنة في جدول `Users` كتجزئة PBKDF2-HMAC-SHA256 (وليست كنص عادي).

الحسابات التجريبية بعد التهيئة:

| المستخدم | كلمة المرور | الصلاحية |
|---|---|---|
| `admin` | `admin123` | مدير (وصول كامل لإدارة المستخدمين) |
| `cashier` | `cashier123` | كاشير |

يُنصح بتغيير كلمات المرور من تبويب **المستخدمون** بعد أول دخول.

تُحفظ إعدادات الاتصال في `config.json` (غير مدرج في Git). كلمة المرور تُحفظ فقط إذا فعّلت «حفظ كلمة المرور»؛ يُنصح بذلك على جهازك المحلي فقط لأنها تُخزَّن كنص عادي.

## الواجهة

- **لوحة التحكم**: بطاقات مؤشرات قابلة للنقر (مبيعات اليوم، عدد المنتجات، المخزون المنخفض، العملاء، إجمالي المبيعات، الموردون) تنتقل بك إلى التبويب المناسب، مع ملخص لأحدث الفواتير والمنتجات منخفضة المخزون.
- **تنقل جانبي**: الشريط الجانبي يحمل أيقونات SVG مخصصة لكل شاشة، وشريط أدوات علوي أزراره أيقونية (تغيير الاتصال، تغيير المستخدم، تبديل المظهر، خروج).
- **المظهر**: زر في شريط الأدوات يبدّل بين الوضع الفاتح والداكن، ويُحفظ اختيارك في `config.json` (أو أضف `"theme": "dark"` يدويًا).
- **المبيعات**: اختيار العميل وطريقة الدفع (نقدي/بطاقة/آجل)، إدخال المنتج بالاسم أو الباركود، الكمية وسعر الوحدة، ثم حفظ الفاتورة. الحفظ في معاملة واحدة: الفاتورة + تفاصيلها + خصم المخزون + تسجيل حركة مخزون + إضافة رصيد للعميل عند الدفع الآجل. منع البيع بأكثر من المتوفر.
- **المنتجات**: إضافة/تعديل/حذف وبحث بالاسم أو الصنف أو الباركود، مع سعر تكلفة وحد إعادة طلب.
- **الأصناف** و**العملاء** و**الموردون**: إضافة/تعديل/حذف مع منع حذف أي سجل مرتبط بعمليات مسجلة. من شاشة العملاء يمكنك **سداد رصيد الآجل**.
- **المشتريات**: فواتير شراء تزيد المخزون وتحدّث سعر التكلفة وتسجل حركة مخزون؛ إلغاء الفاتورة يخصم الكميات again مع التحقق من توفرها.
- **المرتجعات**: إرجاع أصناف من فاتورة ضمن الكمية المتبقية القابلة للإرجاع، مع إعادة الكميات للمخزون وتعديل رصيد العميل الآجل، ومنع حذف فاتورة لها مرتجعات.
- **حركات المخزون**: سجل لكل شراء وبيع ومرتجع وتعديل، مع فلترة بالمنتج ونوع الحركة والتاريخ.
- **المستخدمون**: إنشاء/تعديل/حذف حسابات التطبيق والصلاحيات (للمدير فقط) مع إمكانية تغيير كلمة المرور.
- **التقارير**:
  - جدول المبيعات مع فلترة بالتاريخ والعميل، تفاصيل الفاتورة عند اختيارها، وإجمالي المبيعات.
  - حذف فاتورة مع إعادة الكميات إلى المخزون (ما لم تكن مرتبطة بمرتجع).
  - تقرير المخزون مع خيار عرض المنتجات منخفضة الكمية فقط.
  - رسوم بيانية: مبيعات آخر 7 أيام والمنتجات الأكثر مبيعًا.

## قاعدة البيانات (الإصدار 2)

الجداول: `Users`, `Categories`, `Suppliers`, `Products`, `Customers`, `Sales`, `SaleDetails`, `Purchases`, `PurchaseDetails`, `SalesReturns`, `ReturnDetails`, `StockMovements`.

من أبرز الإضافات:

- Audit fields (`CreatedAt`, `UpdatedAt`) على الجداول الرئيسية، وربط العمليات بالمستخدم `UserID`.
- `PaymentMethod` في الفواتير مع رصيد آجل للعملاء وعمليات سداد.
- فواتير شراء وموردون، ومرتجعات تفصيلية، وسجل حركات مخزون متطابق مع أرصدة المنتجات.
- `MinQuantity` لحد إعادة الطلب، و`CostPrice` لحساب التكلفة، وباركود فريد للمنتجات.

## بناء نسخة Windows (.exe)

لا يدعم PyInstaller البناء المتبادل (cross-compile) من Linux؛ لذلك البناء يجب أن يتم على Windows. طريقتان:

- **تلقائيًا:** كل `push` على `main` يشغّل `.github/workflows/build-windows.yml` على جهاز `windows-latest`. بعد اكتماله حمّل الأرتفاع (artifact) باسم `SupermarketDB-windows` من تبويب **Actions** في GitHub، ثم شغّل `SupermarketDB.exe` من داخل المجلد.
- **محليًا:** على Windows شغّل `build_windows.bat`. النتيجة في `dist\SupermarketDB\SupermarketDB.exe`.

النسخة المبنية تتضمّن `sql/SupermarketDB.sql` وأيقونات SVG، لكنها لا تتضمّن برنامج ODBC؛ يجب تثبيت ODBC Driver 17/18 على جهاز المستخدم. تُحفظ إعدادات الاتصال والمظهر في `%APPDATA%\SupermarketDB\config.json`.

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| «لم يتم العثور على برنامج ODBC» | ثبّت ODBC Driver 17/18 for SQL Server وأعد تشغيل التطبيق |
| «فشل تسجيل الدخول» | راجع اسم المستخدم/كلمة المرور أو اختر مصادقة Windows |
| «كلمة المرور غير صحيحة» (دخول المستخدم) | استخدم `admin123` / `cashier123` بعد التهيئة، أو غيّرها من تبويب المستخدمين |
| «تعذّر فتح قاعدة البيانات» | نفّذ `sql/SupermarketDB.sql` أو استخدم زر التهيئة |
| «تعذّر الوصول إلى السيرفر» | تأكد أن خدمة SQL Server تعمل وأن اسم السيرفر صحيح |
| لا تظهر الرسوم البيانية | تأكد أن `PySide6` مثبّت بالكامل (يشمل `QtCharts`) |

كل استعلامات البرنامج تستخدم معاملات مُرقّمة (parameters) وليس دمج نصوص، والأسعار تُعامل كـ `Decimal` لتجنب أخطاء الفاصلة العائمة، وعمليات الفواتير تتم داخل معاملات قاعدة بيانات واحدة.
